## 任务目标

解决进入工程与页面切换卡顿，从阻塞边界、加载依赖和数据通知架构减少工作量，避免仅增加防抖/缓存或人为延迟。

## 当前项目现状

- Windows Flutter 应用，版本 1.0.0+365；直接 sqlite3 同步数据库，Provider + ValueNotifier 业务状态。
- 主工程目录为本仓库；上级 E:/APP/film 不是 Git 仓库。
- 已有性能探针、文件可用性缓存、预览解码限制、快照保存队列，不重复另建同类设施。
- 原有卡死报告针对文件对话框；当前任务需单独验证普通点击链路。

## 技术方案

1. **存储边界**：初始化/迁移/完整性检查等全库任务移出 UI isolate；核查高频查询和写入事务，按量级选择针对性的异步执行边界。禁止通过同步等待后台结果或不可靠的内存镜像伪装异步。
2. **工作区生命周期**：让后台业务与页面展示职责清晰，保留任务连续性与远程访问；避免为了保活持续布局和执行非必要计算。
3. **数据通知**：基于不可变对象身份、变更范围和查询意图计算，避免每次进度/选择变化全库读取或全量序列化。
4. **可观测性**：复用 PerformanceProbe，记录工程打开各阶段与组件工作量；为可重复大工程夹具记录耗时与响应性。

架构参考：[Flutter isolates](https://docs.flutter.dev/perf/isolates)、[Flutter performance best practices](https://docs.flutter.dev/perf/best-practices)。具体实现以本机 Flutter SDK 和当前项目调用链为准。

## 验收标准

- 迁移/完整性检查保留数据安全保障，耗时操作期间 UI 事件可继续执行。
- 未激活页面不额外参与可避免的布局/重建；页面状态和后台任务不丢失。
- 进度/选择通知不触发无关数据全量查询、全量序列化。
- 工程打开、切换、关闭及远程访问回归通过。
- 记录真实执行的测试、构建、测量与未覆盖边界；没有实机证据不宣称所有用户工程均已丝滑。
