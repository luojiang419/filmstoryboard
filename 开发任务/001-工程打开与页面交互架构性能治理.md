## 任务目标

解决进入工程与页面切换卡顿，从阻塞边界、加载依赖和数据通知架构减少工作量，避免仅增加防抖/缓存或人为延迟。

## 当前项目现状

- Windows Flutter 应用，版本 1.0.0+365；直接 sqlite3 同步数据库，Provider + ValueNotifier 业务状态。
- 主工程目录为本仓库；上级 E:/APP/film 不是 Git 仓库。
- 已有性能探针、文件可用性缓存、预览解码限制、快照保存队列，不重复另建同类设施。
- 原有卡死报告针对文件对话框；当前任务需单独验证普通点击链路。

## 技术方案

1. **存储边界**：初始化/迁移/完整性检查等全库任务移出 UI isolate；核查高频查询和写入事务，按量级选择针对性的异步执行边界。禁止通过同步等待后台结果或不可靠的内存镜像伪装异步。
2. **工作区生命周期**：让后台业务与页面展示职责清晰，保留任务连续性与远程访问；避免为了保活持续布局和执行非必要计算。
3. **数据通知**：基于不可变对象身份、变更范围和查询意图计算，避免每次进度/选择变化全库读取或全量序列化。
4. **可观测性**：复用 PerformanceProbe，记录工程打开各阶段与组件工作量；为可重复大工程夹具记录耗时与响应性。

架构参考：[Flutter isolates](https://docs.flutter.dev/perf/isolates)、[Flutter performance best practices](https://docs.flutter.dev/perf/best-practices)。具体实现以本机 Flutter SDK 和当前项目调用链为准。

## 架构结论与取舍

| 层次 | 原有问题 | 本轮实现 |
| --- | --- | --- |
| 工程会话 | 打开混合 schema/全库审计/历史目录探测，销毁依赖固定延时 | worker 准备数据库和目录检查，真实帧释放后关闭；关闭 finally 释放锁，清理失败不回退到已关闭会话 |
| 模块加载 | 页面懒加载但远程注册强制构造全部控制器，默认设计页间接加载裁切 | 远程 deferred factory，首次桌面/远程使用共享实例；存在可恢复生成任务时仍恢复后台任务；设计结果异步载入，裁切按使用加载 |
| 状态传播 | 本地每条进度事件重建草稿、远程事件全量 DTO/查文件、画板全量 JSON 比较 | 业务字段身份订阅；远程只发布失效通知，按需读取快照；只对变化画板编码；草稿单事务提交 |
| 视图生命周期 | Offstage 保活仍布局，活动切换导致 Selector 重跑整个 builder | RetainedPage 分离状态、布局、语义、焦点与播放生命周期；Selector 复用未变的 Builder 子树，隐藏期间积累最新状态 |
| 大列表与媒体 | 生成表格全量构建，资产页单个 ListView 子节点嵌入全部镜头，原生播放器随条目增长 | 两个列表按视口惰性创建，原生内联播放器按用户播放创建、同一时刻只保留一个、隐藏时释放 |
| 查询与能力判断 | 每行读取全视频帧、多次排序镜头；导出按钮计算全时间线并同步查所有文件 | 预览元数据按刷新加载、动作分组按镜头列表身份索引；按钮只判断元数据候选，实际导出再验证文件和生成时间线 |

下一步完整数据库 worker 迁移应以 Repository 的异步事务命令为单位，连同持久化排空协议逐模块迁移，禁止同步等待 RPC、不能采用不可靠内存镜像替代持久化。本轮优先消除了实测秒级阻塞来源，未为架构形式重写全部业务系统。
