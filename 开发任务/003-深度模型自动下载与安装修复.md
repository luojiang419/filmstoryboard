## 任务目标

修复安装后深度图不可用的问题。安装包不包含模型权重；用户首次提取深度图时自动补齐模型，在原安装目录中断点下载并显示明确的 0–100% 进度，完成后继续提取，无需手动部署。

## 当前项目现状

- `PersonDepthService.resolveComponent()` 要求 worker 和两份模型同时存在，缺失即抛错。
- Windows Release 和 Inno Setup 都会递归复制完整 `person-depth`，导致安装包约 3.33 GB。
- 深度提取界面只有不确定进度的圆形动画。
- worker stderr 仅保存在内存最后 8 行，没有落盘诊断日志。

## 技术方案

- 使用模型官方 Hugging Face 固定 revision URL，下载到现有 `{app}\data\person-depth\models`。
- 下载写入 `.part` 文件，按已下载长度发起 Range 请求；服务端不支持 Range 时安全重下。
- 两份模型按总字节数统一计算进度；下载完成后核对大小和 SHA-256，再原子改名。
- 模型已存在时校验通过后报告 100%，随后启动 worker；下载失败保留合法 `.part` 供下次续传。
- 深度服务用专用 ValueListenable 输出模型准备进度和文案，精确资产区域显示线性进度条、百分比及下载字节。
- 深度服务关键阶段、worker stderr 和失败信息写入 `data/logs/person_depth.jsonl`。
- CMake 仅清理 Release 中两份陈旧权重和复制清单，复制组件时排除 `.safetensors`；Inno Setup 再次排除模型作为防线。不删除安装目录中的既有模型。

## 验收标准

- 缺少模型时点击提取会自动下载，不再提示运行复制脚本。
- 下载过程中持续显示整数百分比，成功时显示 100%，随后自动继续深度推理。
- 中断后可从 `.part` 继续；错误下载不会成为正式模型文件。
- 下载后的两份模型大小和 SHA-256 与锁定值一致。
- Release 目录和安装包均不含 `.safetensors`，但 worker 与模型配置文件完整。
- 深度相关日志可在 `data/logs/person_depth.jsonl` 查看。
- 相关测试、静态检查、Windows Release 和 Inno Setup 编译通过。
