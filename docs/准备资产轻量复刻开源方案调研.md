# 准备资产轻量复刻开源方案调研

调研日期：2026-08-20

## 结论

不建议用某个开源项目整体替换现有 Flutter 复刻模块。当前应用已经具备 Gemini Interactions、多图上传、资产库、任务持久化和生成结果管理，缺少的是更轻的默认交互，而不是另一套工作流引擎。

本次采用的方案是：以 Gemini 官方多图编辑能力为内核，默认只提交有序参考图和紧凑自然语言关系；将原有视觉分析、DWPose、主体决策、产品标识授权、细节回填和姿势审核保留为可选“精确模式”。

## 调研项目

| 项目 | 可借鉴能力 | 不直接引入的原因 |
| --- | --- | --- |
| [GoogleCloudPlatform/vertex-ai-creative-studio](https://github.com/GoogleCloudPlatform/vertex-ai-creative-studio) | Nano Banana 2 / Pro、角色一致性、Shop the Look、资产库、继续编辑 | Apache-2.0，参考价值高；但项目明确是演示用途，依赖 Python、Mesop、Vertex AI 和 Google Cloud，不适合作为现有桌面应用内核 |
| [ru4ls/ComfyUI_Nano_Banana](https://github.com/ru4ls/ComfyUI_Nano_Banana) | 最多 14 张参考图、多轮对话、Gemini API / Vertex AI、图片融合 | MIT 且能力完整；但节点图工作流比当前页面更重，适合作为外部高级工作台，不适合默认创作者流程 |
| [markfulton/NanoBananaEditor](https://github.com/markfulton/NanoBananaEditor) | 自然语言编辑、历史版本树、撤销/重做、局部遮罩 | 体验可借鉴；但基于旧 Gemini 2.5 Flash Image、最多两张参考图，并采用 AGPL-3.0，不适合直接复用源码 |
| [Comfy-Org/ComfyUI](https://github.com/Comfy-Org/ComfyUI) | 成熟的节点执行、队列和插件生态 | 适合复杂本地扩散模型管线；对“一句话多图复刻”属于额外复杂度 |

## 官方能力依据

[Gemini API 图片生成文档](https://ai.google.dev/gemini-api/docs/image-generation) 明确支持文本与图片组合编辑、对话式多轮修改和高级多图构图。官方当前建议优先使用 Gemini 3.1 Flash Image（Nano Banana 2），并说明其可在单一工作流中保持最多 4 个角色的相似度和最多 10 个物体的细节保真度；Gemini 3 Pro Image 适合更复杂、控制要求更高的专业素材制作。

这与产品分层一致：

- 快速模式：Nano Banana 2 优先，一次提交，图片编号和自然语言关系为主。
- 精确模式：需要严格产品、Logo、姿势或主体去留控制时使用现有重流程。
- 续改：生成后采用会话上下文做一次一个变化的小步修改，不重新运行整套资产分析。

## 已落地的交互原则

1. 图片 1 固定为原分镜，只承担动作、构图、机位和光影参考。
2. 图片 2 起依次绑定人物、服装/产品、背景和其他参考图，界面与最终请求编号一致。
3. 用户输入一句自然语言关系，不自动扩写为长篇确定性协议。
4. 快速模式不调用视觉分析、DWPose、产品细节回填或姿势审核。
5. 精确模式保留旧能力，避免高约束商业场景回退。
