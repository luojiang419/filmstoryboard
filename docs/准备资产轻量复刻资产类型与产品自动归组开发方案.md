# 准备资产轻量复刻资产类型与产品自动归组开发方案

## 1. 文档状态

- 项目：filmstoryboard
- 模块：拍摄脚本复刻 / 准备资产 / 快速模式
- 当前待发布版本：`1.0.0+323`
- 方案状态：已确认，等待新任务实施
- 方案原则：轻量、有序、可解释；不恢复原帧分析、DWPose、主体决策、产品回填和自动纠偏重流程

## 2. 任务目标

将快速模式的准备资产流程优化为：用户按顺序添加资产图，为每张图选择类型并可选填写描述，系统固定显示图1至图N；视觉模型结合图片、类型、描述和右侧补充说明自动规划引用关系，其中多个产品主图按从左到右编号为产品A、产品B、产品C，产品细节图自动归入对应产品；最终生成紧凑、规范、适合 Nano Banana Pro 多参考图编辑的提示词。

用户不需要选择“关联主资产”。产品与细节的关系由系统自动整理，系统内部可以保存自动归组结果，但不得在快速模式增加手动关联控件。

## 3. 已确认的交互规则

### 3.1 入口与资产格

1. 将可见文案“添加补充资产”“添加其他参考”等快速入口统一为“添加资产图”。
2. 图1固定为原分镜，负责动作、主体位置、景别、机位、构图、透视和光影方向。
3. 新资产严格按成功加入当前镜头的顺序成为图2、图3、图4，不允许图片数组与页面编号分别排序。
4. 每张资产卡左上角显示稳定的“图N”角标。
5. 快速模式第一版不提供拖拽排序；删除中间资产后连续重编号，并重新生成规划和提示词。
6. 最后一个空资产格未完成上传时，不继续创建新的空格，避免空洞编号。

### 3.2 每张资产卡的字段

每张用户资产图包含：

- 类型：必选。
- 描述：可选，多行输入。
- 自动归组结果：只读，仅产品和产品细节类型显示，例如“产品A”“产品A · 细节2”。

类型集合：

- 模特
- 场景
- 服装
- 鞋子
- 配饰
- 产品
- 产品细节
- 道具
- 风格参考
- 其他参考

描述为空时，系统依据类型生成通用用途；描述不为空时，描述是该图片用途和保真内容的强约束。系统不得虚构用户没有提供的品牌、文字、颜色、材质或结构。

### 3.3 右侧补充说明

快速模式右侧字段统一显示为“补充说明（可选）”。

补充说明参与最终规划，用于描述人物、产品、穿戴、持握、摆放、场景及整体效果之间的关系。显式用户说明优先于类型默认推断，但不得改变图片编号及图片提交顺序。

## 4. 产品A/B/C自动归组

### 4.1 产品主图编号

按页面图片顺序扫描：

```text
图4：产品       -> 产品A
图5：产品细节   -> 产品A细节候选
图6：产品细节   -> 产品A细节候选
图7：产品       -> 产品B
图8：产品细节   -> 产品B细节候选
```

- 第一个“产品”类型资产成为产品A。
- 后续“产品”依次成为产品B、产品C、产品D。
- 显示标签来自当前从左到右的主图顺序；系统内部使用主图资产 ID 作为稳定分组键，不能把字母当作永久主键。

### 4.2 细节图归组证据优先级

1. 描述明确指定图片编号，例如“图4裤子的腰头细节”。
2. 描述明确指定产品编号，例如“产品A的正面细节”。
3. 描述中的产品名称与某个产品主图描述匹配。
4. 视觉模型判断主体、轮廓、颜色、材质、结构和局部特征相似。
5. 左右顺序兜底：归入左侧最近的产品主图；若细节位于所有产品前面，则归入视觉模型判断的最相近产品。

用户明确写出“产品A”时，视觉相似性不得静默覆盖用户意图。若文字与视觉证据明显冲突，仍按用户描述归组，并返回非阻塞警告供界面显示。

### 4.3 描述规范化

需要识别并规范化：

- 产品A的细节
- A产品的腰头
- 产品A正面
- 图4的背面细节
- 黑色裤子的口袋
- 第一件产品的材质
- 产品B鞋底

只自动替换完整的“产品A/产品B”规范标记，不修改普通文本中的单独字母。删除产品主图或改变类型导致A/B重排时，用两阶段占位符方式安全更新规范标记；无法安全更新时保留原文并重新调用视觉规划。

## 5. 轻量视觉规划

### 5.1 调用边界

视觉规划不是原来的完整图片分析，不生成场景分析、人体姿势、主体去留或产品长描述。它只完成：

- 识别产品主图与产品细节之间的关系。
- 规范资产的用途说明。
- 合并每格描述和右侧补充说明。
- 输出结构化引用计划。

单产品且顺序明确时允许本地直接归组，避免无意义的模型调用。出现以下任一情况时调用轻量视觉规划：

- 两个及以上产品主图，同时存在产品细节图。
- 产品细节出现在第一个产品主图之前。
- 描述引用产品A/B、图N或产品名称，需要统一解析。
- 本地规则得到多个候选产品。
- 用户修改了可能改变归属的类型、图片或描述。

规划输入使用有序图片、类型、单图描述、右侧补充说明和本地初步分组。规划结果按图片指纹、顺序、类型、描述和补充说明的联合指纹缓存。

### 5.2 结构化规划协议

视觉模型返回 JSON，不直接自由编写最终提示词：

```json
{
  "productGroups": [
    {
      "label": "A",
      "masterImage": 4,
      "detailImages": [5, 6]
    },
    {
      "label": "B",
      "masterImage": 7,
      "detailImages": [8]
    }
  ],
  "references": [
    {
      "imageNumber": 5,
      "role": "productDetail",
      "assignedProduct": "A",
      "normalizedDescription": "裤子正面门襟、口袋和剪裁细节",
      "evidence": "description",
      "confidence": 1.0,
      "warning": ""
    }
  ],
  "normalizedSupplement": "图3的模特穿产品A，在图2的场景中做图1的动作。"
}
```

规划结果必须通过本地校验：

- 所有图片编号真实存在。
- `masterImage` 必须是“产品”类型。
- `detailImages` 必须是“产品细节”类型。
- 一个细节图最多归入一个产品。
- 存在产品主图时，每个细节图必须得到分组或明确警告。
- 模型不得添加输入中不存在的图片编号。
- 模型不得重新排列实际提交图片数组。

校验失败时使用本地顺序规则兜底，不阻断整个快速复刻流程。

## 6. 数据结构设计

现有 `ScriptShotAssetLink.sortOrder` 同时承担精确模式语义槽位，不能继续复用为快速模式的严格图片顺序。建议新增快速模式专用字段：

- `quickReferenceOrder`：当前镜头内图2至图N的严格顺序。
- `quickReferenceRole`：快速模式类型。
- `quickDescription`：当前镜头内的单图描述。
- `quickGroupAnchorAssetId`：系统自动生成的产品主图资产 ID，仅内部保存，不提供手动关联控件。
- `quickGroupConfidence`：自动归组置信度。
- `quickGroupWarning`：自动归组警告。

同一资产在不同镜头中可能承担不同用途，因此快速类型、描述和归组应属于镜头绑定关系，而不是覆盖资产库全局元数据。

旧链接字段为空时，首次读取按当前链接顺序回填连续顺序，并根据现有 `ReplicateAssetType` 映射默认快速类型，确保旧工程可打开。

## 7. 最终提示词编译

视觉模型负责结构化规划，本地 `LightweightReplicationPromptCompiler` 负责最终确定性编译，确保编号、图片数组和提示词引用完全一致。

编译顺序：

1. 单图输出目标。
2. 图1动作与摄影基准。
3. 场景资产。
4. 模特资产。
5. 产品A/B/C主图及各自细节证据。
6. 服装、鞋子、配饰和道具关系。
7. 每格描述。
8. 右侧补充说明。
9. 比例、透视、接触、穿戴、遮挡、材质和光照统一要求。

产品组提示词模板：

```text
Product A uses Image 4 as its master reference. Preserve its complete silhouette, cut, proportions, color, material, and overall construction. Images 5 and 6 provide the local construction and craftsmanship details described for Product A. Keep Image 4 authoritative for the overall product form while accurately applying the visible local evidence from Images 5 and 6.

Product B uses Image 7 as its master reference. Preserve its own complete form, proportions, material, color, and construction. Image 8 supplies only the assigned local details for Product B. Keep Product A and Product B visually distinct, with each product using evidence from its own reference group.
```

产品细节无描述时使用通用模板：

```text
Image 5 is a detail reference for Product A. Preserve the visible local structure, material, seams, surface finish, and craftsmanship details from Image 5 while keeping Image 4 authoritative for the overall product form.
```

提示词遵循 Google Nano Banana 官方原则：明确多图职责、具体说明高保真细节、复杂组合使用分步指令、使用正向语义表达预期结果，并保持紧凑，避免恢复精确模式的长协议。

## 8. 模型限制与提示

根据 Google 官方 Nano Banana 图片生成文档，Gemini 3 图片模型最多接收14张参考图片；Nano Banana Pro 对高保真对象、角色和风格参考还有更小的分类上限。页面需要按当前模型能力动态显示计数，并把图1计入总输入数量。

当产品主图或细节图数量超过当前模型高保真对象能力时，生成按钮禁用并显示具体超限原因，不能只显示笼统错误。

官方参考：

- https://ai.google.dev/gemini-api/docs/image-generation
- https://ai.google.dev/gemini-api/docs/models/gemini-3-pro-image

## 11. 验收标准

1. 快速模式可见入口统一为“添加资产图”。
2. 图1至图N连续显示，实际模型请求图片数组与UI编号逐项一致。
3. 用户资产必须选择类型，描述可以为空。
4. 一个产品时，所有合理的产品细节自动归入产品A。
5. 多个产品按从左到右成为A/B/C，细节结合描述、视觉相似性和顺序自动归组。
6. 描述中的“产品A”“图4”及产品名称能够成为强归组证据。
7. 用户无须操作关联控件；自动归组结果可解释、有置信度、有警告和稳定兜底。
8. 每格描述和右侧补充说明均进入最终提示词，空描述生成类型通用语句。
9. 产品主图控制整体版型，细节图只补充局部证据；产品A/B细节不串组。
10. 快速模式不调用原帧分析、DWPose、主体决策、产品回填和姿势纠偏。
11. 精确模式、旧工程和旧资产绑定行为不回归。
12. 相关定向测试、完整 `flutter test` 和 `flutter analyze` 通过，Windows Release可启动并完成实际布局检查。
