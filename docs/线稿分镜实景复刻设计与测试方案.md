# 线稿分镜实景复刻设计与测试方案

## 1. 任务目标

在“拍摄脚本 → 准备资产 → 一键复刻”中自动识别由软件生成的线稿分镜，并切换到线稿专用的实景化复刻协议：

- 线稿只负责画幅、景别、机位、透视、主体数量、位置、尺度、姿态、朝向、接触、遮挡和空间拓扑。
- 模特、产品、配饰和场景资产分别负责其被授权的真实外观，禁止不同槽位互串或平均融合。
- 线条、排线、纸张/灰底、分镜人偶脸、简化服装、线稿颜色与线稿光影不得进入成图。
- 没有场景资产时，依据线稿的空间语义和拍摄脚本保守还原为可信实景；不得沿用黑白线稿媒介，也不得自由改构图。
- 最终输出真实摄影质感的实景分镜，而不是线稿上色、插画、3D 预览图或相似镜头重做。

本任务先完成 10 轮同素材、同模型、同参数的提示词对照测试；由用户选出两组，再融合并重复测试 3 轮。只有稳定性测试通过后，才把最终规则集成到生产代码。

## 2. 当前链路与根因

当前 Nano Banana Pro 精准复刻协议把图片 1 定义为“原视频帧编辑底图”，并允许它在没有场景资产时提供：

- 环境外观；
- 环境光色；
- 被选择原帧元素的外观；
- 原人物/原产品在“保留”决策下的真实外观。

线稿分镜与原视频帧的权威范围不同。若继续沿用现有协议，模型容易：

1. 把铅笔线、排线、白底或分镜人偶当成应保留的像素外观；
2. 生成“线稿上色”或半写实插画，而不是实景照片；
3. 把线稿人物的脸、服装轮廓与模特/产品资产混合；
4. 因“编辑底图”要求过强而拒绝重建真实材质、光照和体积；
5. 因“自由重绘”要求过强而丢失原构图、透视、左右位置和遮挡。

因此不能只追加一句“生成实景”，必须把“结构权威”和“外观权威”从协议层分开。

## 3. 开源方案调研结论

### 3.1 ControlNet Lineart / Scribble

ControlNet 的核心做法是把线稿、边缘、姿态、深度等作为额外条件，锁定空间结构，同时让基础扩散模型负责最终图像外观。ControlNet 1.1 的 Lineart 模型明确支持手绘线稿输入。

- 官方仓库：https://github.com/lllyasviel/ControlNet
- ControlNet 1.1 Lineart：https://github.com/lllyasviel/ControlNet-v1-1-nightly/blob/main/README.md

可迁移到当前多图提示词的规则：线稿是结构条件，不是像素底图，也不是风格参考。

### 3.2 T2I-Adapter Sketch / Lineart / OpenPose / Depth

T2I-Adapter 使用轻量适配器把草图、线稿、姿态和深度等条件注入图像生成，并允许与主体外观条件组合。官方 SDXL 版本同时提供 Sketch、Lineart、OpenPose 和 Depth 模型。

- 官方仓库：https://github.com/TencentARC/T2I-Adapter

可迁移到当前多图提示词的规则：

- 不同参考图只提供单一授权维度；
- 线稿负责构图与轮廓，姿态图只负责关节，人物图只负责身份，产品图只负责产品外观；
- 最终图由各条件组合生成，而不是对任一参考图做整图风格迁移。

### 3.3 对本项目的落地选择

本项目现有 Gemini 3 Pro Image / Nano Banana Pro 多图链路已经具备多参考图合成能力，不新增本地 ControlNet 模型和 GPU 依赖。采用“ControlNet/T2I-Adapter 的条件解耦思想 + 现有逐图权威协议”的提示词级方案：

1. 图片 1 从“编辑底图”改为“线稿结构蓝图”；
2. 图片 1 只拥有结构权威，不拥有媒介、颜色、材质、身份和产品外观权威；
3. 模特 A/B、产品 A/B、配饰 A 按槽位独占外观权威；
4. 无场景资产时，环境外观为“受结构约束的保守实景合成”，不属于图片 1 的外观继承；
5. 使用像素空间锚点、透视拓扑、遮挡关系和最终复核抑制构图漂移。

## 4. 测试素材映射

固定参考图顺序：

1. 线稿分镜：服饰/帽饰店双人物广角镜头；
2. 模特 A：画面左侧人物身份；
3. 产品 A：模特 A 穿着的蓝色抽绳直筒牛仔裤；
4. 模特 A 配饰：棕色涂层帆布、浅色皮革包边的肩背包；
5. 模特 B：画面右侧人物身份；
6. 产品 B：模特 B 穿着的橙色高腰阔腿牛仔裤。

固定业务约束：

- 模特 A 与产品 A、配饰 A 绑定；模特 B 与产品 B 绑定。
- 模特 A/B 不得互换左右位置、脸、发型、肤色、体型或服装。
- 产品 A/B 不得串穿、混色、改变裤型或继承模特素材中的原裤装。
- 配饰 A 只给模特 A；不改变线稿人物的主体中心、身体朝向和主要手臂动作。
- 配饰图中的品牌文字、图形商标和水印未获授权，只保留包型、材质、颜色、包边、肩带和结构。
- 实景为可信的现代服饰/帽饰精品店；严格保持线稿中的左右货架、中央纵深展示台、前景帽子、背景衣架、两人位置和遮挡关系。

## 5. 10 轮提示词测试矩阵

所有测试固定：通过 `imgx` 调用 `gemini-3-pro-image-preview`、16:9、2K、同一组参考图、同一参考图顺序。首轮无场景对照使用 6 张图；补充场景资产后使用 7 张图（第 7 张为场景图）。10 个不同提示词以并发数 10 同时提交，每轮只改变提示词协议。

| 轮次 | 方案 | 单一主要变量 | 预期验证点 |
|---|---|---|---|
| T01 | 现有协议对照组 | 图片 1 仍按普通原帧编辑底图处理 | 记录线稿泄漏和实景化失败基线 |
| T02 | 结构/外观权威分离 | 图片 1 只提供结构，其他图提供外观 | 是否摆脱线稿媒介并保持布局 |
| T03 | 线稿蓝图重建 | 明确“从结构重新渲染实景”，禁止像素编辑语义 | 是否减少线稿上色、插画和纸面感 |
| T04 | 像素空间锚点 | 锁定两人中心、前景/中景/背景和左右占比 | 人物位置、尺度和主体平衡是否稳定 |
| T05 | 透视与遮挡拓扑 | 锁定消失方向、展示台纵深、手/帽/桌接触遮挡 | 空间关系是否接近线稿 |
| T06 | 槽位独占外观 | 强化 A/B 人物、产品和配饰一一绑定 | 是否消除串脸、串裤、串配饰 |
| T07 | 分阶段内部执行 | 先解码结构，再装配资产，最后材质化/打光 | 复杂多图是否更完整地被使用 |
| T08 | 摄影媒介复位 | 用真实镜头、材质、体积光和自然皮肤建立实景寄存器 | 是否彻底消除插画/3D/线稿质感 |
| T09 | 紧凑层级协议 | 删除重复约束，按高优先级层级压缩提示词 | 是否因注意力更集中而提升稳定性 |
| T10 | 综合确定性协议 | 融合 T02-T09 的强项并增加提交前核对 | 是否形成首轮候选稳定规则 |

每轮保留：完整提示词、生成结果、模型参数、参考图清单、生成时间、失败信息和人工评分栏。

### 5.1 含场景资产的复跑

用户补充 `测试/资产图/场景.png` 后，使用同一 T01-T10 矩阵重新并发生成，参考图顺序变为：线稿、模特 A、产品 A、配饰 A、模特 B、产品 B、场景资产。场景图只提供店铺材质、灯光、柜体、玻璃和陈列外观；其中的 Louis Vuitton、BeautyNEXT、广告字样、人物海报、水印和可读数字均明确列为禁止继承内容。

- 结果目录：`测试/线稿实景复刻测试/10轮-有场景资产-20260820-2330/`
- 结果：10 成功、0 失败，并发数 10。
- 选优工作簿：`outputs/lineart-replication-20260820-with-scene/线稿分镜实景复刻-10轮测试-含场景资产.xlsx`
- 可复现命令：`run_lineart_live_action_imgx.ps1 -IncludeSceneAsset -OutputDir <输出目录>`

## 6. 用户选择后的 3 轮稳定性测试

用户从 T01-T10 中选择两组。后续流程：

1. 提取两组中真正不同且有效的规则，不简单拼接整段提示词；
2. 去除冲突、重复和过长约束，形成一个融合候选；
3. 使用完全相同的 6 张参考图、模型和参数重复生成 3 次；
4. 比较三次结果的构图、人物身份、产品、配饰、实景质感和异常项；
5. 三次均达标后冻结规则版本并进入软件集成。

## 7. 生产代码设计

- `generic_edit`
- `aspect_expansion`
- `line_art_storyboard`
- `high_definition_redraw`

### 7.2 线稿源协议

增加线稿源模式，贯穿：

- 资产清单；
- 权威范围策略；
- 自动复刻正文；
- Nano Banana Pro 最终编译器；
- 测试与诊断记录。

普通视频帧继续使用现有协议，不改变已有行为。

### 7.3 权威范围变化

| 视觉维度 | 普通原视频帧 | 线稿分镜 |
|---|---|---|
| 画幅、景别、机位、构图、透视 | 图片 1 | 图片 1 |
| 姿态、位置、朝向、接触、遮挡 | 图片 1 / DWPose | 图片 1 / DWPose |
| 环境外观与光色（无场景资产） | 图片 1 | 保守实景合成，不继承线稿媒介 |
| 人物身份和脸 | 模特资产或保留原帧人物 | 模特资产；“保留”仅保留角色存在和结构 |
| 产品外观 | 产品资产或保留原帧产品 | 产品资产；线稿轮廓只作结构提示 |
| 线条、排线、纸面、灰底 | 可作为原画面像素存在 | 无权威，必须转换为真实材质、体积和光照 |

## 9. 验收标准

### 9.1 单图视觉验收

- 人物数量准确为 2，模特 A 在左、模特 B 在右。
- 两个主体中心位置相对线稿的偏移不超过画面宽/高的约 3%。
- 景别、相机高度、透视消失方向、中央展示台纵深和前中后景遮挡保持一致。
- 模特 A/B 身份不互换、不融合；脸、发型、肤色和体型可辨识。
- 产品 A/B 一一对应，裤型、颜色、结构和材质明确，不串穿、不混色。
- 模特 A 的配饰存在且只属于模特 A，不改变主要姿态；品牌文字、Logo 和水印不出现。
- 输出为可信实景摄影：自然皮肤、真实布料、玻璃、木材/金属、体积和阴影完整。
- 不出现铅笔线、墨线、排线、纸面、黑白插画、漫画、概念图、3D 人偶或线稿底图残影。
- 不出现字幕、标题、镜号、界面、任意新增文字或未授权标识。

### 9.2 三轮稳定性验收

融合提示词连续 3 次生成均满足上述硬标准；允许非关键材质纹理和小型背景陈设变化，但不允许：

- 左右人物/产品槽位变化；
- 主体数量变化；
- 主要构图和透视变化；
- 产品颜色、裤型或配饰归属变化；
- 任一次退回线稿、插画或 3D 风格。

### 9.3 软件回归验收

- 普通原视频帧复刻提示词和提交顺序保持不变。
- 1.0.0.328 已生成线稿可通过历史提示词标记识别。
- 新生成线稿可通过显式操作类型稳定识别。
- 一键复刻、单镜头复刻、批量复刻均使用同一分流规则。
- 数据库迁移、单元测试、Widget 测试、静态分析、Windows Release 和安装包校验全部通过。
