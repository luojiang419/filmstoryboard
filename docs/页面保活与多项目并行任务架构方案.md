# 页面保活与多项目并行任务架构方案

## 一、任务目标

1. 顶层页签切换时不销毁已访问页面，保留 Widget State、滚动位置、输入内容、面板展开状态和临时交互状态。
2. 将长耗时任务从“当前选中对象 + 单一全局忙碌标志”改为“按实体 ID 隔离的任务会话”。
3. 不同拍摄脚本、视频和故事板之间可以并行提交和执行；同一实体的重复操作继续防重。
4. 异步回写始终使用任务启动时捕获的实体 ID，不依赖完成时的当前选择。
5. 进度、错误、取消和完成状态归属到对应实体，切回后立即恢复。

## 二、问题根因

### 2.1 页面状态丢失

`AppShell` 使用 `AnimatedSwitcher + switch (_tabIndex)` 只创建当前页。切走后旧子树被卸载，页面级 `State` 和其中的控制器随之销毁。

### 2.2 任务串行与状态串扰

- 拍摄脚本构建将 `isBusy/message/run` 放在单一 `ReplicateState` 中，异步回调多处读取 `value.shots/value.run`。
- 视频解析使用全局 `_continueAnalysis/_cancelAnalysisRequested/isAnalyzing`，只能表示一个视频任务。
- 故事板视觉任务使用单一 `_visionTaskQueue`，不同画板被人为串行化；图片生成也只有全局计数。
- 任务完成时如果用户已切换选择，直接对 `value` 回写可能覆盖新项目的可见状态，甚至使用新项目的数据继续后处理。

## 三、目标架构

### 3.1 懒加载常驻页面容器

- `AppShell` 维护已访问页索引集合。
- 首次访问时创建页面；之后使用稳定索引位置的常驻子树显示/隐藏，不再重建页面 State。
- 非活动页使用 `Offstage + TickerMode` 停止绘制和动画，但保留状态与后台监听。
- 页签顺序和关键 Key 保持稳定，避免因导航位置变化导致子树错位。

### 3.2 按实体隔离的任务会话

每类控制器维护以业务主键为 Key 的运行态：

| 模块 | 任务 Key | 独立状态 | 防重粒度 |
| --- | --- | --- | --- |
| 拍摄脚本/构建 | `scriptId` | 构建进度、消息、错误、活动计数 | 同一脚本同类构建 |
| 视频解析 | `videoId` | 解析、暂停、取消、进度、结果消息 | 同一视频解析 |
| 故事板视觉任务 | `boardId + kind` | 解析/重排运行态、取消标记 | 同一画板同类任务 |
| 故事板图片生成 | `boardId` | 活动计数、消息 | 同一格位/同一生成请求 |

任务入口在启动时生成不可变上下文，包含实体 ID、输入快照、持久化运行记录和取消令牌。异步回调只更新该上下文及对应数据库记录；只有当该实体仍为当前选择时，才同步到可见 `value`。

### 3.3 取消边界

- 取消方法显式针对当前实体 ID。
- 逻辑取消令牌按实体隔离，不得使用一个全局 bool。
- 如底层客户端只支持“取消全部请求”，不在单项目取消时调用该方法；当前请求返回后终止该会话，避免伤及其他项目。
- 销毁整个工程控制器时仍可执行全局取消和资源关闭。

## 六、验收标准

1. 已访问页面在往返切换后保持同一 State 实例，页面内未持久化的输入与滚动状态不丢失。
2. A 脚本构建未完成时，B 脚本的“构建”按钮可用且能立即提交；A/B 最终结果分别存入各自 run 和脚本。
3. A 视频解析中可启动 B 视频；切回 A/B 时显示各自进度；取消 A 不会终止 B。
4. A 画板解析/重绘中可启动 B 画板对应任务；任务按钮、进度和取消仅反映当前画板。
5. 任何后台任务完成时，不会把结果写到当前已切换的另一实体。
6. 新增精确回归通过，原有相关测试通过，`flutter analyze` 无新问题，全量测试通过。
