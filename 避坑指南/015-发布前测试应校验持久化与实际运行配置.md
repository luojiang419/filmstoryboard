# 发布前测试应校验持久化与实际运行配置

## 问题

发布 `1.0.0.132` 前的完整测试发现三项断言与实际契约不一致：数据库迁移已经执行到 9 版但常量仍为 7；APIMart 旧设置只写入兼容字段，未同步实际被路由器读取的 API 卡片；脚本创建后从仓储重载，测试错误比较了两个不同实例。

## 处理

- 将 `AppDatabase.currentSchemaVersion` 与最后一个迁移版本同步为 9。
- 在 `setImageGenerationApiMartSettings` 中规范化地址后同步所有 APIMart API 卡片，确保旧设置入口与实际生图请求使用同一地址和 Key。
- 对持久化后重载的脚本按稳定主键 `id` 断言，不按对象引用断言。

## 以后检查

发布前必须执行完整 `flutter test --no-pub`。涉及兼容字段与新配置卡片时，应同时覆盖“写入入口”和“最终请求提供者”两端的断言。
