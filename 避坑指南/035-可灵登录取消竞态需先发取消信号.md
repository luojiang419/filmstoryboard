# 035 - 可灵登录取消竞态需先发取消信号

## 问题

实现可灵浏览器授权等待时，取消按钮需要同时停止等待循环并终止 `kling login` 进程。

最初顺序是先 `kill()` 登录进程，再完成取消信号。测试中出现竞态：登录进程的 `exitCode` 可能先于取消信号返回，等待循环会把 `exitCode != 0` 判定为登录失败，导致用户点击“取消”后状态变成 `failed`。

## 修复

取消流程必须先完成取消信号，再终止登录进程：

```dart
_completeLoginCancelSignal();
_loginProcess?.kill();
```

等待循环收到取消信号后返回 `KlingLoginAuthorizationStatus.canceled`，不会再把被动退出的登录进程误判为失败。

## 后续注意

- 涉及“取消 + 终止进程 + 等待 exitCode”的流程时，优先发出业务取消信号。
- 不要只依赖进程退出码判断用户意图。
- 可灵登录完成状态仍以 `who_am_i --quiet` 成功为准，浏览器拉起和进程退出都只能作为辅助信号。
