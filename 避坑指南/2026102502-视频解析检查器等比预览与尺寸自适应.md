# 视频解析检查器等比预览与尺寸自适应

[CODEX_LONG_TASK_CONTINUE_V3]

## 问题与证据

右侧检查器把视频预览与解析详情放在同一个 ListView 中，预览使用固定最大高度 440。竖屏素材在较矮窗口下占据大部分侧栏，下方状态、操作和解析内容需要滚动整个预览才能看到。侧栏默认宽度固定为 310，也不会随窗口尺寸改变。

用户截图还显示暂停画面缩在黑色预览区域中央。对本机同名 `480×864` 源视频前 0.5 秒执行 FFmpeg `cropdetect`，结果为 `crop=480:864:0:0`，未发现内嵌黑边。播放器纹理缩放的具体运行时原因尚未经过真实窗口验证，不把这一现象归因于已确认的底层播放器缺陷。

## 实现

- 默认侧栏宽度按工作区宽度的 26% 计算，并限制在 260～400 逻辑像素内；继续受三栏最小宽度约束。手动拖动宽度、收起和展开操作保留。
- `VideoAnalysisInspectorLayout` 根据实际宽高计算最大等比预览尺寸，为详情保留最多 224 逻辑像素的基础空间，小面板按可用高度的一半预留。预览始终可见，详情单独滚动。
- 选中镜头帧时，使用该帧的抽帧图与实际宽高比直接显示，`BoxFit.contain` 保留完整画面；点击仍打开原视频的全屏预览并定位到该帧时间戳。没有选中帧时继续使用原有视频播放器。
- 复用 `PreviewFileImage` 的视口解码尺寸缓存，避免小侧栏解码不必要的全尺寸图片。

主要文件：

- `lib/features/video_analysis/presentation/video_analysis_page.dart`
- `lib/features/video_analysis/presentation/video_analysis_inspector_layout.dart`
- `test/features/video_analysis/video_analysis_page_test.dart`
- `test/features/video_analysis/video_analysis_inspector_layout_test.dart`

## 构建环境恢复

本机旧的 `build/windows/x64` 使用 Ninja，而 Flutter 3.41.7 默认调用 Visual Studio 18 2026 生成器，直接构建会报生成器冲突。旧 Ninja 配置重新生成后还出现 MSVC `/wd\"4100\"` 参数转义错误。这些错误发生在既有原生构建配置，与本次 Dart 布局修改无关。

保留旧缓存到 `build/windows/x64-ninja-preserved-20261025`，在原路径重新生成标准 Visual Studio 构建。新目录下载原生依赖失败时，从保留目录复用 ONNX Runtime 1.22.0、libmpv 与 ANGLE 缓存；libmpv 和 ANGLE 压缩包 MD5 分别为 `a832ef24b3a6ff97cd2560b5b9d04cd8`、`e866f13e8d552348058afaafe869b1ed`，与插件声明一致。

配置阶段中途失败后，还需核对 `CMAKE_INSTALL_PREFIX`。本机缓存曾落到 CMake 默认的 `C:/Program Files/filmstoryboard`，导致 Flutter 报编译成功而 Release 目录只有 EXE。显式将该缓存项设置为工作区的 `build/windows/x64/runner/Release`，重新配置并执行 `cmake --install ... --config Release`，确认 `data/app.so`、Flutter DLL、插件和资源都在 EXE 旁。自动审批拒绝执行清理误生成副本的命令（`blocked by policy`），该默认目录副本保留，不影响工作区产物。当前运行的 `D:/Program Files/故事板` 安装版未修改。

仅在本地 feature branch `codex/adaptive-analysis-inspector` 工作，不推送 GitHub，普通调试不递增正式版本。构建依赖解析造成的 lockfile 与自动生成文件变动已恢复，避免混入无关改动。
