# 010 原图细节导出与高清重绘提示词

## 1. 原图细节导出测试断言不能继续要求降采样

旧导出逻辑按画格宽度解码源图，因此性能测试曾断言 `decodedWidth < intrinsicWidth`。切换为原图细节模式后，正确行为是：当源图大于画格时，解码宽度应等于源图原始宽度，最终导出画布宽高应不小于源图尺寸。后续新增导出模式测试时应同时验证：

- `standard` 保持画板逻辑尺寸。
- `sourceDetail` 保留源图像素细节。

## 2. Canvas 放大必须和图片解码一起处理

只把 `Picture.toImage` 的目标宽高放大，会得到放大的低清图片；只把源图解码到原尺寸，又会让文字和间距比例不一致。正确链路是：先计算源图相对画格的放大比例，再对 Canvas 统一 `scale`，并将 `targetWidth` 同步乘以该比例。

## 3. 高清重绘提示词要定义为修复而不是重新生成

仅写“提升清晰度、细节、光影”容易让模型重构人物或背景。应明确：

- 参考图是唯一视觉依据。
- 任务是超分辨率修复，不是重新创作。
- 只恢复有视觉证据支持的细节。
- 逐项列出保持不变的构图、人物、镜头、光线、材质和文字标识。
- 将故事描述放在辅助语义区，并声明不能覆盖参考图。

## 4. 模型输出档位要和请求参数一致

提示词写 4K 但请求参数仍为 2K 会产生冲突；本次已同步将高清重绘请求的 `imageSize` 改为 `4K`，并保留模型目录对 4K 的支持。

## 5. 全量 Flutter 测试需要关注重复测试包装和并发

项目中的 `test/features/storyboard_controller_test.dart` 会转发到 `storyboard_controller_batch_flutter_check.dart`。两者被全量扫描时可能重复注册共享临时资源，默认并发执行会出现不稳定失败。发布验收使用以下串行命令：

```powershell
D:\flutter\bin\flutter.bat test --concurrency=1
```

本次串行验收结果为 `294` 项通过、`2` 项环境跳过。

## 6. 版本递增必须同步更新器常量

递增版本时不能只修改 `pubspec.yaml` 和 Inno Setup 脚本，还要同步：

- `lib/features/updater/domain/app_update_config.dart` 的 `currentVersion`。
- `currentVersionTag`。
- 发布说明和版本一致性测试期望。

本次从 105 升到 106 后，更新器常量短暂遗留 105，最终被 `updater_service_test.dart` 的版本一致性测试发现，已修复为 `1.0.0.106` / `v1.0.0.106`。
