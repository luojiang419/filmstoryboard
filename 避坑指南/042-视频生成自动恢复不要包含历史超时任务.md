# 042-视频生成自动恢复不要包含历史超时任务

## 问题

视频生成页打开后，如果数据库里有 `timedOut` 历史任务，页面可能显示“正在恢复查询 ... 个任务”，并让 `state.isBusy=true`。由于单镜头和批量生成按钮都依赖 `!state.isBusy`，用户会看到生成按钮持续灰色。

## 原因

`timedOut` 为了支持“稍后继续查询且不重复提交”，被纳入了 `listRecoverableTasks()`。但页面启动时的自动恢复也复用了同一队列，导致超时历史任务被自动恢复，最长可能占用页面 15 分钟。

## 规避

- 服务层默认恢复队列可以继续包含 `timedOut`，保留手动恢复/重启恢复的安全语义。
- 页面控制器的自动恢复应显式传 `includeTimedOut: false`，只恢复 `submitting / queued / running`。
- 遇到“按钮灰 + 顶部提示正在恢复查询”时，优先检查 `video_generation_tasks` 里是否有 `timedOut` 历史任务。

## 相关验证

- `video_generation_database_test.dart` 覆盖 `includeTimedOut: false` 排除超时任务。
- `video_generation_controller_test.dart` 覆盖视频 API 初始化不会被历史超时任务锁住 `isBusy`。
