# 083 - CLI 参数列表断言应定位选项值而非匹配子串元素

## 问题

LibTV CLI 服务测试使用 `contains('提示词片段')` 断言参数列表，实际列表元素是带有镜头前缀的完整提示词，因此功能正确但断言失败。

## 原因

Matcher 的 `contains` 作用于 `List<String>` 时检查完整元素相等，不会对子元素执行字符串子串匹配。

## 解决

先定位 `--prompt` 的索引，再对它后面的完整参数使用字符串 `contains` 断言。

## 后续规则

测试 CLI 参数时，键值型选项统一先定位选项名，再校验紧邻的参数值；只有参数本身应完整相等时才直接对列表使用 `contains`。
