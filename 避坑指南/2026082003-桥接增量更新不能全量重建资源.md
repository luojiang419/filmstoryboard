# 桥接增量更新不能全量重建资源

## 问题

同一桥接故事板重复接收时，即使 board ID 和 asset ID 保持一致，先删除整个任务的 `cut_results` 再 INSERT 仍不是增量更新：所有记录的 `created_at` 会改变，数据库通知范围扩大，资源缓存也无法区分真实变化项。

## 解决

1. 用 `external-cut:<frame stable_id>` 作为资源实体主键。
2. 用包含 SHA-256 的本地 path 作为内容版本。
3. 比较既有记录，只对 path、index、width、height 或 selected 改变的记录执行 UPDATE。
4. 缺失稳定 ID 才 DELETE，新增稳定 ID 才 INSERT。
5. 故事板同步成功后再清理不再引用的旧内容文件。

## 验证要求

测试不能只断言“最终图片正确”，还必须断言未变化记录的 path 和 `created_at` 均不变，变化记录的 path 改变但 `created_at` 仍保留，新删记录数量准确。
