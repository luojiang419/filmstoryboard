# 022 - Windows 视频下载长路径与过期提示词夹具

## 问题一：服务端生成成功，本地下载仍可能失败

### 现象

可灵任务已经返回视频 URL，但 `.mp4.part` 重命名或写入时报 `PathAccessException`、`errno = 5`。

### 根因

不能只清理文件名。若父目录直接拼接完整脚本名或提示词，Windows 最终路径仍可能过长；在部分 API 中表现为“拒绝访问”，容易被误判成权限问题。

### 规避

- 对每一级生成目录设置明确长度上限；
- 始终追加短 ID 保证截断后的唯一性；
- 结果文件只使用镜号和任务短 ID；
- 服务端已有结果 URL 时提供独立重新下载入口，禁止用“重新生成”代替下载重试。

## 问题二：过期提示词测试不能手工塞入不完整记录

### 现象

步骤 3 新增镜头指纹校验后，Widget 测试手工插入 `rawResponse: ''` 的提示词，再刷新时记录会被自动清理，导致“下一步”按钮禁用。

### 根因

生产逻辑将缺少 `shotFingerprint` 的记录视为旧版或脏数据，这是正确行为；测试夹具绕过了真实合成入口。

### 规避

需要有效提示词的测试应调用 `composeAllPrompts()`，或完整构造与当前镜头一致的指纹和双版本字段，不应放宽生产校验。

## 问题三：Windows 路径断言需要规范化

`Directory.systemTemp` 与 `path.join` 可能分别保留 `/` 和 `\`。比较文件路径前应使用 `path.normalize`，避免把表现形式差异误判为文件选择错误。
