# 098：准备资产展示顺序与生成请求顺序职责分离

日期：2026-08-17

## 问题现象

为满足 Nano Banana 请求的“模特 A → 产品 A → A 细节 → 模特 B……”稳定图片顺序，直接把准备资产页的预设槽也改成交错顺序后，已有页面拖拽测试无法把资产从右侧资产库稳定拖到“模特 B”。

根因不是拖拽逻辑本身，而是把两个不同职责混为一体：

- 准备资产页的展示顺序服务于用户操作，原有“所有模特在前”能让同类槽位保持邻近和稳定布局。
- 生成请求顺序服务于模型输入编号，必须按人物与产品绑定组交错排列。

当槽位数量增加后，交错展示让“模特 B”跨入新的 Wrap 位置，既改变了用户操作习惯，也让测试中的拖拽轨迹跨越更多目标。

## 解决方式

- `ScriptAssetSlotPolicy.presetSlotsFor` 保持页面友好的顺序：模特 A/B… → 产品 A/细节 A → 产品 B/细节 B… → 场景。
- `ReplicateController` 在生成引用时单独按权威顺序组织：模特 A → 产品 A → A 细节 → 模特 B → 产品 B → B 细节 → 场景。
- 最终请求还应由 `NanoBananaAssetManifest` 再做一次不可变编号，不能依赖页面顺序。

## 同类问题预防

- 不要把 UI 展示排序、持久化排序号和外部 API 输入排序视为同一个概念。
- 新增槽位时先检查 Wrap/滚动/拖拽页面测试，不要只验证领域列表。
- 外部模型图片编号必须在请求边界生成不可变清单，避免 UI 调整改变模型语义。
- 旧持久化排序号必须保留：产品 A=2000、产品 A 细节=2001、产品 B 起=2100；新增产品 B 细节从 2200 段开始，场景使用 3000，避免与旧产品 C 等槽位碰撞。

## 验证

- 准备资产页面完整测试 15 项通过。
- 复刻控制器测试 17 项通过。
- 全量测试 726 项通过、2 项跳过、0 失败。
