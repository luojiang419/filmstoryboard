# 092 - 源码字符串测试需随函数签名结构改动同步更新

## 问题现象

业务代码分析通过、运行逻辑未报错，但页面测试因 `contains(...)` 查找旧函数调用文本而失败。

本次旧断言：

```dart
contains("_shouldExpandWorkGroup(group, controller)")
```

函数接入文件缓存后新增 `BuildContext` 参数，实际调用变为：

```dart
_shouldExpandWorkGroup(context, group, controller)
```

## 原因

该测试检查源码结构而非执行行为。函数签名发生合理变更后，旧文本断言不会自动适配，因此产生结构性误报。

## 解决方法

1. 先确认静态分析通过，并核对失败位置只是源码文本断言。
2. 确认新参数确实参与目标行为，而不是意外改名或漏调用。
3. 只更新对应断言，不放宽成过于模糊的匹配。
4. 重新运行页面测试和相关控制器测试，确保不仅是“改测试过关”。

## 后续规避

- 修改被源码结构测试覆盖的类名、函数名或调用签名时，同步搜索测试中的字符串断言。
- 能用行为测试覆盖时优先行为测试；必须验证静态结构时，断言应聚焦关键结构，不重复绑定无关格式。
- 遇到此类失败先区分“业务回归”与“结构断言过期”，避免为迎合旧文本回退正确设计。
