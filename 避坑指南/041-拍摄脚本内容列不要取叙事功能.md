# 041-拍摄脚本内容列不要取叙事功能

## 问题现象

拍摄脚本/复刻流程里的“内容”“画面描述”列显示成“建立”“推进”“广告产品记忆点”“静态展示”等短标签。

这些词来自视频解析的 `narrativeFunction`，属于镜头叙事作用，不是可供脚本确认和复刻使用的画面内容。

## 原因

从视频自动生成 `ScriptShot.content` 时，候选字段顺序错误：

```dart
sourceShot?.storyFlow
sourceShot?.description
dimensions['narrativeFunction']
dimensions['caption']
```

而 `VideoShot.storyFlow` 本身通常也由 `narrativeFunction` 写入，因此只要它非空，脚本内容列就会被叙事功能抢占。

## 正确做法

脚本内容列只能优先取画面描述类字段：

```dart
dimensions['caption']
sourceShot?.description
dimensions['detail']
```

不要把 `narrativeFunction` 或 `storyFlow` 当作 `content` 的兜底来源。

## 后续注意

- `narrativeFunction` 可用于视频解析报告、镜头节奏判断、提示词辅助维度，但不能直接覆盖拍摄脚本“内容/画面描述”。
- 修复旧工程时不要全量覆盖 `script_shots.content`，否则可能误删用户手动编辑内容；应只在内容等于叙事功能标签或旧 `storyFlow` 且能找到对应 `caption` 时再替换。
- 现有工程的受控修复应在脚本加载/刷新时执行，并同时满足：
  - 镜头关联 `sourceVideoFrameId`
  - 对应帧有已完成的 `VideoFrameAnalysis`
  - `caption` 非空
  - 当前 `content` 精确等于 `narrativeFunction` 或 `VideoShot.storyFlow`
- 旧工程不一定保存了脚本级 `sourceVideoId`。修复逻辑不能依赖 `shooting_scripts.source_video_id`，应通过每个镜头的 `script_shots.source_video_frame_id` 直接查询 `video_frame_analyses.frame_id`。
- 旧值可能是常见叙事标签，例如“建立”“推进”“广告产品记忆点”“静态展示”。这些短标签在确认镜头表里出现时，应按帧解析 `caption` 修复。
- 不能把空内容、人工长文本、产品说明或已经正确的 `caption` 当作旧错误值覆盖。
