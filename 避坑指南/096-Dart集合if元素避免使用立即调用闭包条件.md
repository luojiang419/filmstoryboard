# Dart 集合 if 元素避免使用立即调用闭包条件

## 问题

在集合字面量中写成 `if (() { ... })() reference` 会造成解析歧义，格式化器报告 `Expected to find ','`，编译器还会把闭包本身误判为布尔值。

## 原因

Dart 的 collection-if 语法对紧邻的立即调用闭包不稳定且可读性差，闭包结束、调用括号与后续集合元素容易被解析成不同结构。

## 解决

需要多分支判断集合元素是否保留时，改用普通 `for` 循环：先计算 `include` 布尔值，再执行 `if (include) result.add(item)`。

## 后续约束

- collection-if 只用于简单布尔表达式。
- 需要局部变量、多个早退分支或映射查询时一律使用普通循环或命名函数。
- 修改后先运行 `dart format`，再进入测试，能最快发现语法结构问题。
